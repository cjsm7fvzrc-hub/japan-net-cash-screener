# 日本株テンバガー候補・リサーチ

JPX公式の上場銘柄一覧から、一般投資家向け市場を対象として取得し、GitHub Actions上で `yfinance` を分割実行します。プロ投資家向けのTOKYO PRO Marketは対象外です。結果はSQLite (`data/stocks.db`) に蓄積し、Web画面は書き出されたJSONだけを読みます。ブラウザを閉じても処理は継続します。

## テンバガー候補機能

従来の清原型ネットキャッシュ判定を残したまま、時価総額による成長余地、売上・営業利益の3年CAGR、四半期成長、営業利益率の変化、財務安全性、割安度、52週高値と出来高を統合して0〜100点で順位付けします。

候補は「清原型」「成長初動型」「変身型」「継続観察」に分類されます。点数は将来の株価を予測・保証するものではなく、追加調査の優先順位です。

## 第2段階：変化・触媒モニター

直近四半期の売上・営業利益、3年成長率との差、営業利益率、予想EPS、株価・出来高を組み合わせ、業績変化の兆候を0〜100点で表示します。「上方修正兆候」は会社が公表した業績修正を意味せず、決算・IRを確認する優先順位です。各銘柄から企業サイト、開示情報、TDnetへ移動できます。

## 第3〜5段階：判断・シナリオ・継続監視

- キャッシュフロー、財務安全性、減収減益、利益率悪化、割高性から下振れリスクを評価
- 候補性、触媒、リスク、データ信頼度を統合した総合投資スコア
- EPS成長率、出口PER、期間を変更できる将来株価・年率リターンの感応度分析
- ブラウザ内に保存するウォッチリスト、確信度、投資仮説・撤退条件メモ
- ウォッチ追加時に100株を仮想購入したものとして、投資額・評価額・評価損益・損益率を銘柄別／全体で更新（実際の約定ではなく、保存データの最新株価を使用）
- ウォッチ銘柄のスコア、リスク、株価、上方修正兆候の大きな変化を自動記録

## 銘柄別・詳細投資判断レポート

各銘柄の「詳細レポートを発行」から、事業概要、財務品質、成長、割安性、触媒、リスク、52週価格チャート、移動平均、RSI、ボラティリティ、弱気・基本・強気シナリオ、IR確認リンク、利用者メモをまとめた印刷用レポートを生成します。レポート画面からPDF保存・印刷、または自己完結型HTMLのダウンロードができます。

## 判定条件

- ネットキャッシュ比率 1.00以上
- PER 10倍以下
- PBR 1倍以下
- 時価総額20億円以上（上限なし）
- 流動資産が負債を上回る

対象市場からTOKYO PRO Marketを除外します。

ネットキャッシュ = 流動資産 + 投資有価証券 × 70% − 負債

## GitHubへの設置（パソコン推奨）

1. GitHubで新しい公開リポジトリを作成します。
2. このZIPを展開し、中にあるファイルをすべてリポジトリ直下へアップロードします。
3. リポジトリの `Settings` → `Pages` → `Build and deployment` のSourceを **GitHub Actions** にします。
4. `Actions` → `Update Japanese stock data` → `Run workflow` を実行します。
5. 以後は毎時17分に約200社ずつ自動更新されます。全銘柄を一巡すると次回は先頭から更新します。
6. `Actions` → `Deploy web screen` が完了すると、`Settings` → `Pages` に公開URLが表示されます。

通常、約3,800社なら一巡に約19回かかります。実行遅延を含め、おおむね1日以内で全銘柄がそろう設計です。手動実行時は `batch_size` を変更できますが、対象母集団は常に全上場銘柄であり、画面上の「50社・100社」選択はありません。

## 保存データ

- `data/stocks.db`: 銘柄ごとの最新値を保存するSQLiteデータベース
- `data/results.json`: Web表示用データ
- `data/status.json`: 進捗、最終更新、失敗件数など
- `data/evaluation_history.json`: 週次の候補群・対照群と期間到達後の固定成績
- `data/model_review.json`: データ品質、期間別成績、承認待ちの改善案
- `data/ai_review.json`: 任意のClaude独立監査結果

## 精度検証・改善

全銘柄の更新完了時に週次スナップショットを保存し、30・90・180・365日後の成績を固定記録します。候補群だけを見るのではなく、同時点の低スコア対照群と比較することで、相場全体の上昇をモデルの実力と誤認しにくくしています。

改善案は画面の「精度検証・改善」に表示されますが、判定条件や配点を自動変更しません。最低標本数を満たし、利用者が内容と過剰適合リスクを確認して承認した場合だけ、別の変更として実装します。

Claudeによる月次の独立監査は任意です。有効にする場合はRepository secret `ANTHROPIC_API_KEY` とRepository variable `CLAUDE_MODEL` を設定します。APIキーはWeb画面へ配信されません。未設定または監査失敗時も、通常の銘柄更新と数値検証は継続します。

## 清原式・推定評価

公開された投資上の考え方を参考に、割安性、ネットキャッシュの質、利益と営業キャッシュフロー、資本配分、割安の罠を0〜100点で機械的に評価します。これは清原達郎氏本人の判断を再現・断定するものではなく、銘柄調査を支援するための推定評価です。

EDINETの有価証券報告書も反映する場合は、リポジトリの `Settings` → `Secrets and variables` → `Actions` で、金融庁EDINETから発行されたAPIキーを `EDINET_API_KEY` という名前のRepository secretとして登録します。未登録の場合も、財務数値に基づく暫定評価は動作します。

## 注意

Yahoo Finance側のアクセス制限や勘定科目差により、一部銘柄は取得に失敗することがあります。失敗数は画面に表示され、次の周回で再取得されます。投資判断前に各社IR資料で確認してください。
